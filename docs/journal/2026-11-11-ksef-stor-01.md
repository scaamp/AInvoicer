## Problems Encountered

- help.sap.com renderowane w JS — rozwiązane przez publiczne źródła Markdown SAP-docs (CC-BY-4.0).
- Przypisanie eu20 → Azure pochodzi z materiałów SAP learning/trust center (wyniki wyszukiwania), nie
  z odczytu subaccount; pozostaje do potwierdzenia `cf marketplace -e objectstore`.
- Brak w dokumentacji SAP parametru WORM/immutability dla Object Store — luka opisana w przewodniku.
- `KsefSubmissionWorker.tx` jest package-private — test OUTBOUND umieszczono w pakiecie workera,
  emulator udostępniono jako publiczne fixture testowe; bez zmian kodu produkcyjnego workera.

## Decisions Made

- Provider: SAP BTP Object Store (`standard`) na Azure, protokół Azure Blob REST z container SAS.
- REST na JDK `HttpClient` zamiast `azure-storage-blob`: bez podpisywania, zero nowych zależności; wymiana
  ograniczona do `AzureBlobSasClient` za SPI.
- Scope: OUTBOUND per NIP, INBOUND per środowisko + granty CAP (wymuszone modelem współdzielonego dokumentu).
- Referencja logiczna `ksefdoc:v1:...` bez nazw kont/URL; prefiks wdrożenia w konfiguracji.
- Brak delete/overwrite w aplikacji; orphan tylko raportowany. Brak rejestracji beana — aktywacja w INT-03.
- ADR nie dodano: wybór pozostaje warunkowy (entitlement/koszt); decyzję utrwali INT-03 po zgodzie właściciela.
