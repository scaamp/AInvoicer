# Lokalna konsola H2 w przeglądarce

[Project Home](../README.md) · [STATUS](../STATUS.md) · [ROADMAP](../ROADMAP.md)

## Date

2026-10-24 (Europe/Warsaw).

## Branch

`java-cap-ksef` — sprawdzony przed zmianą.

## Goal

Udostępnić lokalną przeglądarkową konsolę H2 do odczytu i wykonywania SQL w bieżącej bazie CAP Java.

## Initial State

- Drzewo Git było czyste.
- Projekt używa Spring Boot 4.1.1, CAP Java 5.2.0, H2 oraz Spring Security.
- `application.yaml` nie miał jawnego URL H2 ani konfiguracji konsoli. `GET /h2-console/` zwracał 404.
- OData działało wcześniej pod `localhost:8080`; request testowy został utworzony i odczytany przez serwis.

## Implementation

- Dodano `spring-boot-h2console` w zakresie runtime oraz włączenie konsoli pod `/h2-console` tylko dla profilu `default`.
- Nadano Spring datasource stabilny adres in-memory `jdbc:h2:mem:capjava;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE`, aby konsola i CAP wskazywały ten sam datasource.
- Ustawiono `web-allow-others: false`; konsola ma być osiągalna tylko lokalnie.
- Dodano osobny, najwyżej uporządkowany łańcuch Spring Security dopasowany wyłącznie do H2 Console. Wyłączenie CSRF i dozwolone ramki SAMEORIGIN są ograniczone do tej ścieżki; pozostałe endpointy zachowują dotychczasowy łańcuch CAP.

## Changed Files

- `cap-java/srv/pom.xml` — moduł H2 web console.
- `cap-java/srv/src/main/resources/application.yaml` — URL in-memory i lokalne ustawienia konsoli.
- `cap-java/srv/src/main/java/customer/cap_java/H2ConsoleSecurityConfiguration.java` — obsługa CSRF/ramek wyłącznie dla konsoli.
- `docs/STATUS.md`, `docs/README.md` i ten wpis — stan, indeks i zapis sesji.

## Commands Executed

- Odczyt konfiguracji `application.yaml`, POM, kodu Java, statusu Git i dokumentacji CAP Java/Spring Boot.
- `Invoke-WebRequest` na `/h2-console/` przed zmianą — HTTP 404.
- `Invoke-WebRequest` na `/h2-console/` po pierwszej zmianie — HTTP 500; po krótkim czasie `/`, OData metadata i konsola również zwracały HTTP 500.
- Po przeniesieniu URL do `spring.datasource.url`: `/`, OData metadata i `/h2-console/` zwracają HTTP 200; formularz H2 Test Connection zwrócił `Test successful`, a OData odczyt kolekcji zwrócił HTTP 200.
- Maven nie był dostępny w środowisku narzędziowym tej sesji (`mvn` nie jest rozpoznawane), dlatego nie wykonano builda. Bieżący runtime przeładował konfigurację.

## Tests & Results

- Konfiguracja statyczna: zmiany w POM/YAML/Java zostały przejrzane, lecz nie skompilowane.
- Runtime: `/h2-console/` jest serwowane; test połączenia JDBC z konsoli działa. OData odczytuje encję po zmianie datasource.
- SQL z formularza GUI nie zostało jeszcze wysłane. Zmiana/restart procesu może wyczyścić dane, bo H2 pozostaje bazą in-memory.

## Problems Encountered

Początkowy URL w `spring.url` nie wskazywał datasource używanego przez konsolę w uruchomionym runtime; H2 zgłaszało brak `mem:capjava`. Po ustawieniu `spring.datasource.url`, zgodnie z konfiguracją Spring Boot datasource wykorzystywaną przez CAP Java, test połączenia H2 zakończył się powodzeniem.

## Decisions Made

Konsola jest lokalnym narzędziem developerskim, ograniczonym do profilu `default` i połączeń localhost. Nie włączono jej w profilu cloud/produkcyjnym.

## Current State

Konsola działa w bieżącym runtime. URL strony: `http://localhost:8080/h2-console`. JDBC URL: `jdbc:h2:mem:capjava;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE`; użytkownik H2: `sa`, hasło puste — wyłącznie lokalne ustawienie developerskie. Baza została odtworzona jako in-memory po restarcie, więc wcześniejszy testowy rekord nie jest już obecny.
